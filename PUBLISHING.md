# Публікація «Полтава поруч»

Сайт статичний: для хостингу потрібні лише HTML, JavaScript, GeoJSON і фото. Сервер Node.js потрібен для локального перегляду та збирання, на хостингу запускати його не потрібно. Немає бази даних, серверних ключів чи залежності від домену GitHub. Інструкція підготовлена без створення репозиторію, комітів або публікації.

## 1. Правки тільки на комп’ютері

Як і раніше, запускай `start-map.bat`. Для телефона в тій самій Wi-Fi мережі — `start-map-phone.bat`. Зупинка — Ctrl+C у вікні сервера. Зміни в `index.html`, `scripts` і `data` видно після оновлення сторінки. Вони нікуди не надсилаються.

Альтернатива з Node.js 24 або новішим, із папки проєкту:

```powershell
npm start
```

Ця команда відкриває лише локальний сервер: `http://127.0.0.1:8001/`. Установлювати npm-пакети не потрібно — зовнішніх npm-залежностей немає. Не запускай одночасно `npm start` і батнік на тому самому порту.

## 2. Перевірка й готова копія сайту

Двічі клацни `prepare-publish.bat`. Він запускає тести, готує `dist` і ZIP-архів `release/poltava-map.zip`. Успішне повідомлення з’явиться лише після проходження перевірок. Ця дія **не публікує** сайт.

Або виконай команди:

```powershell
npm test
npm run build
npm run preview
```

Попередній перегляд готової копії — `http://127.0.0.1:8002/`. Для зупинки натисни Ctrl+C. Папка `dist` створюється заново при кожному збиранні: редагуй оригінальні файли, а не файли всередині `dist`. Після правок знову виконай `npm run build`.

До готового сайту входять лише потрібні браузеру файли та фото з атрибуцією. Сирі експорти, XLSX, тестові скріншоти, кеш, батніки й скрипти імпорту залишаються поза `dist`. Папки `dist`, `release`, `node_modules` і робочий кеш виключені з Git. Повний вихідний проєкт зберігається окремо від готової копії; ZIP призначений для хостингу, а не як резервна копія коду.

## 3. Перша публікація на GitHub Pages

1. Створи порожній репозиторій GitHub, наприклад `poltava-map`. Для GitHub Free обери **Public**. Якщо це новий порожній репозиторій, не додавай на GitHub початковий README, щоб не створити окрему історію.
2. Завантаж у нього **вихідний проєкт**, включно з прихованою папкою `.github`, `package.json`, файлами `scripts` та `data`. `index.html` і `.github` мають лежати безпосередньо в корені репозиторію, без зовнішньої папки «Poltava Open Data Hackathon».
3. Відкрий **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Перейди в **Actions → Publish GitHub Pages → Run workflow**. Вибери основну гілку репозиторію (зазвичай `main`) та запусти workflow. Файл workflow має вже бути в основній гілці. Для старого репозиторію перевір, що середовище `github-pages` дозволяє публікацію з вибраної гілки.
5. Після успішного виконання відкрий адресу з кроку `deploy` або Settings → Pages. Зазвичай це `https://YOUR-USERNAME.github.io/poltava-map/`. **Не дописуй `/dist/`** до адреси сайту.
6. У Settings → Pages перевір **Enforce HTTPS**, якщо цей перемикач доступний.

Варіант завантаження через Git із термінала в папці проєкту (заміни URL на свій):

```powershell
git status
git add .
git commit -m "Prepare Poltava map for GitHub Pages"
git branch --show-current
git remote -v
git remote add origin https://github.com/YOUR-USERNAME/poltava-map.git
git push -u origin HEAD
```

Команду `git remote add origin ...` виконуй лише якщо `origin` ще немає. Якщо він уже є, перевір правильність URL перед `push`. `git push -u origin HEAD` публікує поточну гілку зі збереженням її назви. Якщо вона називається не `main`, використовуй її фактичну назву в GitHub. Якщо Git просить увійти в GitHub, заверши звичайний вхід у Git Credential Manager/браузері; не вставляй пароль або токен у файли проєкту.

Workflow спочатку запускає тести, потім збирає `dist` і публікує лише цю папку офіційними GitHub Pages Actions. Підготовка даних не звертається до реєстрів: використовуються збережені локальні набори.

Джерела інструкції: [власний workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [HTTPS на GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https).

## 4. Подальші оновлення — тільки коли вирішиш

1. Змінюй сайт локально й перевіряй через `start-map.bat` або `npm start`.
2. Запусти `npm test` та `npm run build`, за потреби перевір через `npm run preview`.
3. Збережи готові зміни комітом і виконай `git push`.
4. Для оновлення публічного сайту **окремо** запусти Actions → Publish GitHub Pages → Run workflow.

У workflow є лише `workflow_dispatch`; автоматичної публікації на `push` немає. Локальні зміни, збирання, коміти й сам push не змінюють уже опубліковану версію. Тому можна зберігати код на GitHub, а публікувати лише готові версії. Не редагуй паралельно той самий проєкт через вебредактор GitHub без подальшого отримання цих змін у локальну копію.

## 5. Перенесення на інший хостинг

1. Запусти `prepare-publish.bat` або `npm run build`.
2. Скопіюй **вміст** `dist` у вебкорінь нового хостингу (наприклад `public_html`) або розпакуй `release/poltava-map.zip` саме туди. `index.html`, `data` і `scripts` мають бути поруч, без додаткової вкладеної папки `dist`.
3. Увімкни HTTPS. Сервер має віддавати `.mjs` як JavaScript (`text/javascript` або `application/javascript`), а `.json`/`.geojson` як JSON. На файловому хостингу важливий точний регістр назв файлів.
4. Для автоматизованого статичного хостингу команда збирання — `npm run build`, вихідна папка — `dist`, Node.js — 24 або новіший. Перенесення самого GitHub workflow не потрібне.
5. Відкрий сайт, перевір завантаження карти, фільтри, картки, «Найближче укриття» та дозвіл геолокації. Для окремого домену браузер запитує дозвіл заново.

Відносні шляхи підтримують і корінь домену, і підпапку на кшталт `/poltava-map/`. Ім’я репозиторію чи домен не зашиті в код. Власний домен і DNS можна підключити пізніше — файл CNAME без відомого домену не створюється.

## Геолокація й зовнішні сервіси

GitHub Pages на `github.io` надає HTTPS, який дозволяє браузеру запитати геолокацію, зокрема на телефоні. Користувач усе одно має надати дозвіл, а пристрій — повернути координати. У разі відмови або помилки залишається ручний вибір місця. На локальному Wi-Fi HTTP автоматична геолокація може блокуватися; це не помилка публікації.

Для підкладки потрібен доступ до OpenFreeMap, для запитаного пішохідного маршруту — до FOSSGIS / OSRM. Точки, доступність і пошук найближчого укриття використовують локальні дані. Їхні наявні обмеження після публікації зберігаються; перенесення сайту не робить дані повнішими чи актуальнішими.

## PWA, офлайн-копія та теми

Після першого відкриття через HTTPS застосунок автоматично зберігає повну локальну копію: інтерфейс, об’єкти, укриття, ознаки доступності, фото, MapLibre з worker, шрифти та базову підкладку центру Полтави. У панелі «Офлайн і встановлення» видно прогрес. **Дочекайся повідомлення «Офлайн-копія готова»**, перш ніж відключати інтернет. Якщо місця недостатньо або завантаження обірвалося, готовність не підтверджується; попередня повна версія залишається доступною.

Офлайн-підкладка охоплює довготи 34.50–34.61 та широти 49.55–49.62 (центр Полтави), містить 58 векторних тайлів масштабів 10–14; при більшому масштабі вони збільшуються. За цією ділянкою об’єкти й укриття доступні, але детальна підкладка без інтернету не гарантується. Кнопка «Показати збережений центр» повертає до неї. Нові пішохідні маршрути вимагають інтернету; пошук найближчого укриття обчислюється локально, також із вручну обраної позиції. GPS залежить від пристрою та дозволів. Зовнішні посилання на джерела без мережі не відкриються.

Місяць у шапці вмикає темну тему, сонце — світлу. Вибір зберігається на пристрої й працює офлайн. При першому запуску використовується системна тема. Зміна теми не скидає фільтри або маршрут.

На Android/комп’ютері встановлення доступне через кнопку «Встановити застосунок», коли браузер її підтримує, або меню браузера. На iPhone — «Поширити» → «На початковий екран». Встановлення не є умовою офлайн-доступу. Браузер може видалити кеш через очищення даних сайту або нестачу місця; тоді потрібно повторно відкрити сайт із мережею й дочекатися готовності. Приватний режим може обмежувати зберігання.

Для звичайних локальних правок використовуй порт 8001 через старі батніки або `npm start`: PWA-кеш на localhost автоматично не реєструється, тому не заважає оновленню файлів. Для перевірки готового PWA:

```powershell
npm run build
npm run preview
```

Відкрий **http://127.0.0.1:8002/?pwa=1**, дочекайся готовності, увімкни «Підкладка центру офлайн» й перезавантаж сторінку без мережі або після зупинки сервера. Це окремий порт, тому його кеш не впливає на звичайну розробку на 8001. Перед поверненням до розробки на тому самому тестовому порту можна очистити дані саме цього сайту в налаштуваннях браузера.

**Перед ручним завантаженням файлів у GitHub запускай `prepare-publish.bat` або `npm run build`.** Збірка оновлює також кореневі `sw.js` та `offline-files.json`. Якщо використовуєш підготовлений GitHub Actions, він виконує це автоматично. Разом із оновленим кодом потрібно переносити нові папки **vendor, icons, styles, data/offline**, а також **manifest.webmanifest, sw.js, offline-files.json**. `dist` і `release` у репозиторій, як і раніше, не додаються.

Версія кешу залежить від вмісту файлів. Після нової публікації користувач бачить «Оновити застосунок»; стара повна копія працює до застосування нової. Самостійно не редагуй згенеровані `sw.js` і `offline-files.json`: шаблон worker — `scripts/sw-template.js`. Повторна збірка не завантажує сторонні дані. Офлайн-пакет уже включено до проєкту; для його цілеспрямованого оновлення існує `node scripts/prepare-offline-map.mjs --refresh`.

Джерело підкладки — OpenFreeMap / OpenMapTiles / OpenStreetMap (ODbL), ліцензія MapLibre збережена у `vendor/MAPLIBRE-LICENSE.txt`, шрифтів Noto Sans — у `data/offline/NOTO-SANS-OFL.txt`. Походження й дата пакета — `data/offline/metadata.json`. Пакет обмежений за розміром, завантажувач використовує максимум 4 паралельні запити та окремий User-Agent згідно з [умовами OpenFreeMap](https://openfreemap.org/tos/). Технічна основа кешування: [Service Worker API](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).

На власному сервері: `.css` має віддаватися як `text/css`, `.mjs`/`sw.js` — як JavaScript, `.webmanifest` — як `application/manifest+json`, `.pbf` — як `application/x-protobuf` (або бінарний тип). Для `sw.js` і `offline-files.json` рекомендується `Cache-Control: no-cache`, для решти — звичайне кешування; не виставляй нескінченний immutable-кеш без версіонування URL. GitHub Pages не потребує додаткової серверної конфігурації.

### Компактний індикатор збереження

Біля перемикача теми є іконка офлайн-копії. ✓ означає перевірену збережену копію, ↓ — завантаження, ! — помилку або неповний кеш, ? — готовність ще не підтверджено. Натискання відкриває відсоток завантаження, дату збереження та кнопку перевірки/відновлення. Перевірка враховує наявність кожного файла в кеші, а не лише запис про завершення. Під час локального запуску без PWA можна явно натиснути «Зберегти офлайн»; звичайні правки краще перевіряти на окремому порту без кешу, як описано вище. Рядка-банера під шапкою немає.

Джерела всієї карти наведені в розділі «Усі джерела даних» у лівій панелі. Для укриттів вказані офіційна сторінка Полтавської ОВА, використаний табличний набір міської ради та адресний реєстр ГІС для координат. Недоступні джерела доступності відокремлено від фактично імпортованих.

### Сервер для повідомлень про неточності

Перед увімкненням реального надсилання виконай [backend/README.md](backend/README.md). Фронтенд залишається статичним на GitHub Pages; окремий Worker передає звернення команді карти. Потрібна лише адреса приймача в `report-config.json`; токен у публічних файлах заборонений. Відвідувач не переходить на GitHub і не входить у нього. Без підключеного сервера доступні форма, локальна чернетка та експорт, але повідомлення не надсилаються. Після зміни адреси перебудуй сайт і онови встановлену PWA.
