# Режим «Без бар’єрів»

## Поведінка

Перемикач біля пошуку відкриває чотири незалежні фільтри: пандус, ліфт, доступна вбиральня, спеціальне паркування. Кілька вибраних ознак означають **усі одночасно (AND)**. Без вибраних ознак потрібна хоча б одна підтверджена. `unknown` та `no` не потрапляють у підтверджені збіги. Пошук, категорії, увімкнені шари й попередній фільтр `wheelchair` застосовуються одночасно.

Маркери, список і лічильник отримують один масив результатів. У звичайному режимі список показує перші 100 результатів із відповідним поясненням; режим доступності наразі містить 63. Окремий шар укриттів у цьому режимі приховано, оскільки чотири ознаки для нього не підтверджені. Вибір зберігається в URL (`bf`, `bf_features`, `q`, `category`, `layers`, `wheelchair`, `sort`), є окреме скидання ознак і всіх фільтрів.

Кожна картка містить усі чотири текстові стани, іконки, посилання на джерела та відомі дати перевірки. Дата знімка бази або завантаження не видається за дату перевірки об’єкта. Загальна оцінка наведена окремо. Суперечливі твердження зберігаються, підсумок такої ознаки — `unknown`.

Наявність окремих елементів не гарантує повної доступності об’єкта. Наявний пішохідний маршрутизатор не перевіряє безбар’єрність усього шляху.

Локальний набір містить 421 об’єкт із відомостями доступності, із них **63** мають хоча б одну підтверджену ознаку: пандус — 29, ліфт — 1, вбиральня — 4, паркування — 29. Наразі це різні об’єкти, тому комбінації двох ознак можуть не мати збігів. Загальні оцінки ГІС не перетворюються на чотири підтвердження.

## Межі та зіставлення

Усі нові записи, туристичні точки й укриття фільтруються точним контуром **міста Полтави**, OSM relation/1641691. Відкинуто 20 OSM-записів і 27 записів ГІС за містом, ще 2 записи ГІС без геометрії. Той самий контур обмежує центр карти, геолокацію, точки A/B та весь маршрут. Технічний відступ камери дозволяє бачити контур цілком, проте не дозволяє вибирати точки за ним. Позаміська геолокація показує «Ви за межами міста Полтави».

Злиття можливе за однаковим ID або єдиним збігом нормалізованої назви, точної вулиці/номера будинку та координат до 35 м. Сама близькість чи спільна адреса не є підставою для злиття. Неоднозначні записи лишаються окремими, а методи зіставлення записані в аудиті. Без спільного ID або достатніх даних різні джерела можуть описувати той самий об’єкт окремо — автоматично вгадувати тотожність небезпечно.

## Оновлення й імпорт

Сайт завантажує лише локальний `data/poltava-accessibility.geojson` один раз; перемикання фільтрів не викликає сторонніх API. Помилка кешу не підставляє вигадані підтвердження. Порожній валідний кеш також підтримується.

```powershell
node scripts/build-accessibility.mjs --refresh
# Якщо сирі завантаження вже є в ігнорованій папці .cache/accessibility:
node scripts/build-accessibility.mjs --cached
```

Для майбутнього експорту ЛУН спочатку перевірити ліцензію, реальні колонки та їхні значення. Адаптер приймає CSV (типово `;`), GeoJSON або JSON-масив. Приклад нижче — **шаблон відповідності, а не реальна схема ЛУН**; усі назви колонок і ліцензію слід замінити перевіреними значеннями. Не вказувати загальну оцінку в `features`.

```json
{
  "source": {
    "id": "lun",
    "name": "ЛУН / Мінрозвитку",
    "url": "https://lun.ua/misto/barrier-free",
    "license": "ВКАЗАТИ ПЕРЕВІРЕНУ ЛІЦЕНЗІЮ ЕКСПОРТУ",
    "status": "connected"
  },
  "id": "actual_id_column",
  "name": "actual_name_column",
  "address": "actual_address_column",
  "longitude": "actual_lon_column",
  "latitude": "actual_lat_column",
  "checked_at": "actual_survey_date_column",
  "general": "actual_overall_verdict_column",
  "features": {
    "ramp": {"field": "actual_ramp_column", "yes": ["yes"], "no": ["no"]},
    "elevator": {"field": "actual_elevator_column", "yes": ["yes"], "no": ["no"]},
    "toilet": {"field": "actual_toilet_column", "yes": ["yes"], "no": ["no"]},
    "parking": {"field": "actual_parking_column", "yes": ["yes"], "no": ["no"]}
  }
}
```

```powershell
node scripts/import-accessibility.mjs --input=export.csv --mapping=mapping.json --output=normalized.geojson
node scripts/build-accessibility.mjs --import=normalized.geojson
```

Координати GeoJSON мають порядок longitude/latitude і систему WGS84; іншу проєкцію спочатку потрібно перетворити. Відсутні поля залишаються `unknown`. Дати перевірки приймаються у форматі ISO `YYYY-MM-DD`. Імпортер відкидає записи за містом і повертає їхню кількість. Після імпорту перевірити аудит, ліцензію, конфлікти й підсумкові кількості перед публікацією.

## Перевірки

```powershell
node --test scripts/accessibility.test.mjs scripts/map-navigation.test.mjs scripts/map-region.test.mjs
```

Перевіряються всі 16 комбінацій фільтрів для всіх 81 наборів yes/no/unknown, перетин з іншими фільтрами, конфлікти, зіставлення без перенесення сусідніх елементів, адаптери, URL, картки, порожні/пошкоджені дані та точний міський контур. У браузері додатково перевірено синхронність карти/списку/лічильника, перезавантаження URL, порожній результат, HTTP 503 кешу зі збереженням звичайної карти, клавіатуру та екран 390×844. Реальний GPS конкретного пристрою не підмінявся і не тестувався; для телефона потрібен HTTPS і дозвіл браузера.
